执行状态：A–F已执行，见 `v0.1.7_functional_verification_report.md`。E的12次短程运行全部提前灭绝，科学判别不足，不列为双向适应验收通过。B/C最终固定面板使用一个预先指定的第0代重复每种前4株，而非汇集所有重复；具体选择及适用边界在报告中公开。两名Sol medium完成数据与检查后受额度/网络限制退出，由主任务接手验证并完成综合报告。

## 1. 基线与范围

使用当前无花期、无交配前寄主定居的v0.1.7（slim-qtl-4 / expression-tuning-2）。已有正式批次为 `results/results_v0.1.7/200gen_H400_corrected_20261029`，只读使用其6组记录、审计和源码快照。不得重写历史数据、元数据或指纹。所有新检查数据、脚本和日志进入 `codex/validation/v017_functional_verification_20261029/`；可复用且确有必要的检查代码进入tests或现有分析入口，不新增绘图入口。

## 2. 工作包与判定

| 工作包 | 执行与比较 | 验收与解释边界 |
| --- | --- | --- |
| A 功能能力清单 | 逐项连接遗传轴、表达/调谐、响应谱、行为、幼虫表现、母源成本与双方后代贡献；列出固定项 | 区分已实现、不能表达、数学假设和可查文献支持。宽度固定不能写成单模块宽度可演化，谱系分群不能写成成种 |
| B 固定条件下的寄主识别 | 使用同一个事先固定的寄主化学面板、相同数量/空间候选，对6个重复第0、50、100、150、200代昆虫重新计算选择概率（含拒绝） | 复用真实选择函数，分别报告寄主概率与拒绝率；不把资源可得性变化或实际寄主份额当作偏好演化 |
| C 固定条件下的利用 | 同一寄主防御与资源面板，使用相同代次昆虫自身模块，比较处理容量、无竞争条件下的摄食/存活期望；明确这不是整世代适合度 | 感知轴单独改变不直接改变处理；处理轴单独改变不直接改变选择。终点缺失/灭绝明确标记，不填成能力为零 |
| D 表达成本对照 | 相同个体、同一固定环境，将现有母源表达成本与零成本配对；必要时加小规模短程对照 | 区分固定状态的直接成本效应与跨代选择效应；不从代数恒等式宣称成本已获实证验证，也不声称已完整检验成本对专化的长期作用 |
| E 双向反馈控制 | 先复用现有配置构造同一单态祖先初态，双方开启变异、仅植物允许变异、仅昆虫允许变异、双方固定，共4情景×3预定种子×10代 | 固定一方必须每个位点初始拷贝相同且无突变、重组不能制造差异，并逐代断言遗传/表达状态不变。只有此条件下关闭突变才构成固定遗传性状；原多态200代批次不能如此解释。仍保留数量、空间与生态反馈。短程检验不要求出现适应或成种 |
| F 植物灭绝过程 | 对已有4次植物灭绝提取末20代的数量、取食损伤、存活、化学成本、局部配偶机会、密度抑制与后代补充，并对照其他存续记录 | 区分直接账本瓶颈与推测的根因；不把时序相关当作因果效应，不挑种子、不提高繁殖率掩盖灭绝 |

B/C的面板以第0代植物的已记录化学状态构造并在所有代次固定；保存具体值、权重与源哈希。不得用每代植物均值悄悄改变共同环境。报告个体分布和各重复变化，不把代内个体当独立重复，不预设改善方向。

E优先使用现有配置和输入接口。单态初态与原正式批次不同，必须明确是独立机制检查，不冒称对原200代结果的直接因果归因。遗传系统若不能用现有接口正确构造固定对照，先修复必要的最小检查实现并记录；不得引入隐含的后代性状覆盖或一个不可验证的“停止演化”开关。种子预定20261021、20261022、20261023；种群规模优先沿用现有小规模机制测试配置，各情景完全相同，不按结果重选。

## 3. 执行顺序与职责

1. Sol medium负责A–E：先核查现有模块及测试、保存设计和固定面板，再完成检查与可复现输出。只改必要的分析/测试代码；发现核心实现错误时说明证据、做最小修复并重新验证，不添加生物机制。
2. 另一Sol medium负责F：只读正式批次，独立生成灭绝过程账本和证据说明，不改核心代码。
3. 主任务复核设计、检查结果与推断边界，整合核定报告；新增文献核实仍由Sol执行，引用原始来源并注明读取深度。已有报告不是所有公式的实验验证。

## 4. 检查和交付

- 设计/输入/源码身份与每个情景的实际配置；所有结果包括失败或无变化情景。
- 固定环境的感知与利用表、成本直接效应、12个短程控制的轨迹和固定性断言。
- 4次植物灭绝的过程表与逐次结论，明确尚不能确定的因果环节。
- `docs/plan/v0.1.7_functional_verification_report.md`：能力边界、各检查是否通过、发现的问题、下一阶段必须修改和暂不需要修改的部分。
- 若改代码，运行Ruff check、format --check和完整tests，日志保存到上述codex目录。检查不通过不得以观察到预期生物结果替代。

完成标准是机制定义清楚、实现与定义一致、关键解释可区分；不是必须产生专化、物种形成或三物种长期共存。最终是否推进寄主关联隔离，由这轮证据决定。
