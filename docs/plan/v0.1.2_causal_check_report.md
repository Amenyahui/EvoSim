## 1. 接续修改时的状态

输入已经迁入 YAML/CSV，v0.1.2 的最小模型规范、对照输入和部分贡献计算、审计代码已经存在，但生成流程尚未接通：网络起始位置未设置，已计算的等位频率和寄主贡献账本未提交到结果，固定面板仍仅输出两个单独均值，保存与审计契约尚不完整。

### 2.1 本次完成的核心代码连接

- `helpers/observations.py` 在个体层先计算 p×q，再做类群汇总，返回个体矩阵供快照保存。
- `helpers/contributions.py` 从已有双亲账本推导贡献，不创建第二套生殖抽样。
- `substeps/reproduction.py` 在后代全部验证后，同时提交个体贡献、寄主贡献网络及等位频率分解；终代和异常回滚不假造贡献。
- `substeps/ecology.py` 增加资源份额，明确贡献尚未提交时的缺失，并保存参考面板的行列对应关系。
- `substeps/demography.py` 区分母源角色与找到寄主的资格：无寄主雌虫的后代期望为零，雄虫的母源期望缺失。
- `batch.py` 保存新增账本及空表列头；参考面板标签不会混入基因型导出。
- `audit.py`、`audit_contributions.py` 从快照、双亲子代身份与生态记录独立重建，不以生产贡献函数自证正确。

字段和缺失含义见 [results.md](results.md)。父本资格门槛、固定物种边界及既有成本函数仍按规范保留。

## 5. 如何复现

从项目根目录执行，输出目录须不存在：

```powershell
python -m ruff check evo_sim tests example.py
python -m ruff format --check evo_sim tests example.py
python -m tests
python -m evo_sim.models.plant_insect.analysis.check_causal_chain --out codex/validation/v012_causal_new
python -m evo_sim --config evo_sim/models/plant_insect/configs/v012_base.yaml --out codex/validation/v012_batch_new
python -m evo_sim.models.plant_insect.audit --input codex/validation/v012_batch_new
python -m evo_sim.models.plant_insect.analysis.summarize_qtl_run --input codex/validation/v012_batch_new
```

通用参数在 YAML，物种与遗传记录在 CSV；对照文件位于 `configs/v012*.yaml` 和 `inputs/v012/`。每次保存解析后的配置、输入来源和哈希，不修改历史结果的元数据。

## 6. 当前仍不能回答什么

这些短程检查不证明稳定寄主关系、长期共存、共同演化或物种形成。形成场景改变了初始变异分布；2P×2H 同时改变同种配偶池；对方组成干预不是单一分子机制干预；搜寻尺度变化可以通过寄主位置进一步影响交配。

父本 `F>0` 门槛仍缺乏直接实证支持，默认域不会触发不等于广参数域可靠。Gaussian/softmax 识别、化学尺度、突变率与连锁距离仍是探索性设定。固定物种网络只能研究已有物种间的关系，不能据此解释新物种多样性的产生。

下一阶段先按用户最新要求完成 [IBM 理论架构定稿决策](v0.1.2_minimal_model.md)：明确生活史、成本角色和竞争作用位置，再判断是否需要改变生成规则。此后才围绕明确假说设计正式比较，确定参数证据、重复与窗口；不把本报告的短程对照直接写成课题的科学发现。
