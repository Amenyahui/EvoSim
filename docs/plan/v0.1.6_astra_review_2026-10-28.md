# v0.1.6 计划独立理论审核（2026-10-28）

审核对象：`docs/plan/v0.1.6_plan.md`；只读对照本地 v0.1.5 源码及正式文档。实际 HEAD 为计划指定的 `cd1dee61735db12027cf27db55945d10ec7f1bf4`。本次仅新增本报告，未修改计划、源码或配置，未执行模拟、测试或参数扫描。文献核实由主代理分派的 Sol 审核者完成，本文不替代其核实结论。

## 结论

**研究方向与模型建设原则基本合理，但目前还不是可以不作理论选择便连续编码的执行合同。** 母体嗅觉选择与子代利用分离、双亲遗传、共享化学成本、真实事件网络的方向正确。必须先修正基线协议、旧交配规则复用、繁殖参数的阶段含义、寄主群遗传输入及贡献账本口径；候选谱系交付范围和初始化边界也要写实。

现有规范能够建设“抽象 QTL—化学/识别/利用功能—幼虫资源竞争—双亲遗传—寄主群与网络”的机制模型。它尚不建设真实 OR/OBP/解毒家族的分子功能模型，也尚无使新物种成立的独立机制。这是能力边界，不能用“本来就不保证出现成种”来替代说明：**允许研究某种现象与保证得到该现象是不同要求。** 本报告不要求强制出现专化、成种或特定网络结构，也不建议拆分版本。

## 必须修正或明确的七项发现

### 1. [P1，确定错误] 遗传协议写成旧版，与保留共享化学模块直接冲突

计划位置：第 28、150、344 行。

证据：`configs/model_parameters.yaml:82` 使用 `slim-qtl-2`；`docs/model.md:3` 同样明确该协议。`helpers/genetics.py:89–94` 将此协议与共享化学映射、植物三维效应绑定；第 90–91 行另有限定 `model_version=0.1.5` 的检查。本文代码路径均以 `evo_sim/models/plant_insect/` 为根。

计划要求保留三模块植物化学，同时三次要求保留 `slim-qtl-1`。这不是无害名称差异：直接照做会遇到协议/映射不一致，或者错误退回旧植物坐标。SLiM 5.2 与 QTL 数据协议是不同层次。

**最小修正：** 全部改为保留实际 `slim-qtl-2` 和 SLiM 5.2；把软件版本兼容检查更新列入迁移任务。计划第 285 行“尚未取得该提交完整代码”也应在本次核验后更新为已核验事实。

### 2. [P1，需理论定稿] “沿用现有交配规则”不能直接接到先交配、后产卵的新生命周期

计划位置：第 55–60、305、319–326、394 行。

证据：`substeps/demography.py:18–28` 从本代取食读取存活概率，并要求昆虫已有寄主、把交配位置移到该寄主格；第 39–51 行先抽存活，再筛实际父本及抽母源产量。`substeps/ecology.py:104–105` 给出植物受食后存活及昆虫 `S=g`。旧模型是本代个体择主取食后交配，新合同则要求已完成上一轮幼虫存活的成虫先交配。

原函数中的 `valid=host>=0` 在新成虫尚未产卵时没有对应含义，雄虫更没有本轮产卵寄主。重复沿用 `S=g` 抽一次会使同一幼虫存活经历再受筛选；沿用“本轮寄主格交配”则依赖尚未发生的选择。这个差异还影响寄主选择与交配隔离的联系：新规则可通过出生地、扩散和局部交配产生关联，但不再自动包含旧版双方先选择当代寄主再相遇的路径。

**最小修正：** 明定成虫的交配位置、是否在交配前扩散、交配候选池，以及已补充成虫不重复抽幼虫生存。可复用同种、性别、距离及均匀抽父本等独立规则，不复用完整旧阶段函数。明确父本是逐子代抽样还是一次配对锁定；旧实现 `substeps/reproduction.py:70–75` 是逐子代抽样，计划伪代码仅列父本池而未选择 `father_id`。

植物边界已有可核验答案：`docs/model.md:7` 与 `docs/architecture.md:33` 是后代整体替换亲代，属于非重叠世代；植物先受食、抽存活、再繁殖。保持该生物学次序可与新幼虫窗口衔接，但需要正式选定 `P_t → 受食/存活/繁殖 → P_{t+1}`，不能仍把是否跨代存活作为未调查事实，也不能用第 394 行“恢复原有时序”替代完整双类群时间表。

### 3. [P1，需理论定稿] 原“有效后代数”被改成潜在卵数，产量参数及抗性成本阶段尚未落定

计划位置：第 64、319、335–340 行。

证据：`docs/model.md:166` 明确旧 `λ` 是每合格母本进入下一状态的有效后代基准，压缩配子、受精和未显式发育阶段；并非逐枚卵数。`substeps/demography.py:19–22` 使用 `μ=λ F_m φ`；`helpers/ecology.py:137` 中昆虫 `F_m=max(0,1-c_I ΣI)`。

新合同把同一分布称作潜在后代，再增加每卵拒绝、子代竞争和存活。这可以成为新模型，但必须重定义 `λ` 的阶段，不能同时保留“有效补充数”的旧解释。它也改变密度制约位置：旧代取食个体数受资源制约，新代是母体潜在卵产量决定进入资源池的幼虫数。

**最小修正：** 明列昆虫 `N_potential(m) ~ Poisson(λ_egg,s F_m(I_m))`、产卵接受、子代出生及 `Bernoulli(x_o/dmax_o)` 补充这几步；这里 `λ_egg` 名称是语义建议，不要求新增第二个参数。若选择沿用旧数值，须声明只是示例基准而非旧模型人口学等价。明确母源抗性成本读取母亲自己的 `I_m`，仅影响其产卵；幼虫 `I_o` 通过摄食进入存活。母亲曾经幼虫摄食的资源收益不再乘一次。线性母源成本可保留，但“成本只计一次”并不等于模型已有闭合碳能量预算；`docs/model.md:91` 明确没有这种预算。

### 4. [P1，定义错误] 跨背景双亲交配不足以定义背景群之间的遗传输入

计划位置：第 360–370 行。

第 366 行把实现的跨背景输入限定为“上述”双亲出生背景不同的后代成功补充。反例：父母均出生于 P1，母体在 P2 产卵，子代在 P2 成活。没有跨背景双亲配对，但 P1 来源的遗传材料已进入 P2 出生群。反过来，父母 P1/P2 混合而子代出生于 P3，也必须说明输入的目的群。

**最小修正：** 保留双亲背景是否不同的配对统计，另按每个成功补充后代记录亲本出生背景到子代出生背景的有向贡献：

`G[a,b,t] = Σ_(o ∈ Adult(t+1)) 1[H(o)=b] × (1[H(m_o)=a] + 1[H(f_o)=a])/2`。

非对角项表示寄主背景之间的核遗传来源输入；全矩阵合计为成功补充数。出生阶段可另存同样口径的矩阵，不能混同补充阶段。此账本仍是寄主群来源流动，不自动证明独立遗传群体、有效迁移率或生殖隔离。最小验收应加入同背景双亲转寄主、异背景双亲产于第三寄主、出生后全部死亡三例。

### 5. [P1，实施合同缺口] 新增幼虫死亡后，出生贡献与成虫补充贡献必须分别守恒

计划位置：第 115、134、366、383–384 行。

前文按成功产生后代记遗传贡献，附录按补充成虫记实现输入，并另提下一轮真正贡献。三者可同时存在，但不能继续只有一个含混的“成功后代”口径。

证据：旧 `helpers/contributions.py:22–27` 从出生计数计算 `(B_m+B_f)/2`，第 45–46 行要求贡献总和等于下一状态人数。`substeps/reproduction.py:156` 直接令 `N_next=N_offspring`。新模型一旦出生十只、仅三只活到成虫，旧等式和等位贡献分解不能原样套用。

**最小修正：** 明定出生账本的和等于出生数，补充账本只在幸存子代上重新累计父母贡献、和等于下一代成虫数；下一轮成虫的实际繁殖贡献再以该轮声明的终点计数。保留全部出生者的亲子及死亡记录，幸存者进入成年状态。对等位频率分解明确比较的是出生子代还是补充成虫。

网络也需固定端点：旧 `helpers/contributions.py:75–100` 将贡献归于每个亲本当代取食寄主；新成虫没有这个事件，应明确改为亲本出生寄主的滞后贡献，或者子代产卵寄主关联，不能只改列名。补充边与资源边分开这一原则本身正确。

### 6. [P2，内部交付冲突] 前文承诺候选谱系出现/消失，附录实际只定义寄主群和亲子图

计划位置：第 135–144、160–175、370、376–378 行。

附录正确指出寄主背景不是谱系，且使用双亲 DAG 保存真实系谱；但没有定义前文候选谱系 ID 的成员、产生、持续、混合及终止条件。双亲 DAG 本身也不是一组互不重叠的谱系：后代有两条祖先路径，不能直接把每个分支当新谱系。

**最小修正：** 如果本版交付就是出生群、完整系谱和固定物种的动态网络，把前文验收统一成这些对象，并明确“尚不生成候选独立谱系”。如果仍要候选谱系对象，须由理论负责人定义它的判定与混合处理，但不要求变成物种或禁止交配。寄主群空缺可随后由别群母体重新占据，不能用物种灭绝那样的永久终止逻辑处理；群消失、谱系消失、物种灭绝分别定义。

这不要求现在发明成种阈值；它要求诚实区分已交付机制和整个研究目标中尚缺的机制。

### 7. [P2，数据因果缺口] 创始出生背景与出生/补充时间索引缺少初始化合同

计划位置：第 55、295–303、325、348–354 行。

证据：`helpers/agents.py:28–36` 的现有昆虫状态没有出生寄主；`helpers/spatial.py:58–75` 只生成初始位置。旧 `substeps/reproduction.py:84` 给遗传后代写 `current_step+1`，计划第 325 行却写 `birth_generation=t`。二者可分别表示事件轮和成虫队列，但同名字段不能混用。

**最小修正：** 创始成虫背景由显式初始输入或 `unknown/founder` 表示，不能把当前位置、最近植物或第一次产卵寄主倒填成出生经历。来源未知的贡献单列，避免漏记导致总账不守恒。定义 `reproduction_round=t` 与 `adult_cohort=t+1` 的映射，同一子代出生至成虫保持 ID，亲代/子代引用包含类群；现有 ID 是类群内唯一，不应假设两类群全局唯一。

终点规则也需一句完整定义：旧模型末代只观察但仍为同一代个体计算假设取食，见 `docs/model.md:7`、`substeps/ecology.py:130`；新成虫没有自己的幼虫取食。若末代不生成子代，就只能保存成年快照/明确标记参考观察，不能伪造下一批幼虫的资源边或把未运行的补充数记成实际零。

## 可以保留的合理简化

- A 是抽象可遗传气味模板，I 是按防御通道的耐受能力；不靠改名冒充 OR/OBP/P450 分子模型。现有默认独立连锁群不等于 A/I 已有紧密连锁，关联可来自选择、漂变和交配；无需为保证关联而新增强制连锁。
- 每个潜在后代独立择主、幼虫固定出生寄主、同批资源比例分配及线性 `S=x/dmax` 可作为明确操作假设。无需先加完整卵蛹阶段、学习、诱导防御或多底物酶动力学。
- 共享化学模块合成成本只计一次，母源繁殖成本不直接取消父本资格，可以保留。`F_m=0` 的雄虫仍可父源贡献并非逻辑漏洞；它是现有成本适用范围的限制。
- 已有同种空间交配与二倍体各半遗传可以保留。各半权重是按亲本角色定义的核遗传来源份额，不保证每个具体等位必定传递，已有 `helpers/genetics.py:412–444` 的亲子和逐位点传递记录足以复用；不需要仅为此升级引擎或新建完整树序列系统。
- 固定物种 ID、寄主群、系谱分开记录且互不暗中控制生态参数是正确约束；无需添加新网络指标。

## 开始编码之前需要的最小定稿

1. 一张双类群时间表：成虫交配位置与扩散、母源产量、逐卵选择、子代取食存活、植物受食后存活繁殖、成年队列替换。
2. 一组阶段清楚的数学定义：母亲成本与潜在卵数、子代资源存活、出生/补充两套亲本贡献、源—目的寄主群贡献。
3. 一份对象范围声明：固定物种、每代出生群、亲子 DAG、候选谱系是否确实存在；创始未知背景与终点未执行事件的处理。

这些是使理论可以唯一落成代码的最低合同，不是提前开展正式分析。定稿后的验收应检查规则、守恒、因果及接口；不能将“出现专化/成种”设为通过条件。
