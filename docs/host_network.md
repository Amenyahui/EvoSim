# 初始寄主网络

当前生态规则 1.6 在第 0 代与后续世代使用相同局部搜索与选择机制。以下初始性状示例对应 evo_sim/models/plant_insect/configs/network_emergence.yaml 的直接性状模式；QTL 配置通过基因型产生性状。

## 初态与事件顺序

配置只给初始数量、可遗传定量性状及空间分布。示例中 P1/P2 各 50 株，H1=10；P1/P2 的防御 D 与气味性状 Z 分别为 `[0.2,0.6]`、`[0.6,0.2]`，H1 的抵抗 I 与识别 A 均为 `[0.2,0.6]`。它们是遗传性状的定量代理，并非 OR/OBP、P450/GST/UGT 的显式基因型。H1 对 P2 的潜在无限资源利用率仍是 1/3，因此初始 P2 取食不需要新突变。

`initial_plant_cells` 与 `initial_insect_cells` 可分别提供每个体的整数坐标，按物种顺序排列；设为 `null` 时，用相互独立的固定种子子流在 10×10 周期栅格均匀取样。位置与植物身份或寄主身份不绑定。每格可以容纳多个体。植物竞争按局部邻域计算，繁殖后代按既有扩散规则落位。

第 0 代与以后各代执行同一顺序：以昆虫起点为中心，在 Chebyshev 距离不超过 2 的格位寻找可见植物；最多随机抽取 8 株候选；用候选气味与昆虫 A 计算识别概率，允许“不选择”；选中后再用植物 D 与昆虫 I 计算可食率 q、实际取食量 x 和繁殖机会。没有候选则记 `no_candidate`；有候选但选择外部选项则记 `rejected`；成功则记 `accepted`。这是一轮局部遭遇，并没有连续飞行轨迹、气味扩散场或主动趋化。

可用 `events.csv` 的 `candidate_plant_ids`、`candidate_count`、`reason`、`host_id`、`q`、`x` 区分遇见、选择与取食；`networks.csv` 的 `candidate_exposure`、`N_accept`、`Q_actual` 汇总为物种边。`diagnostics.csv` 的标准参考面板用于比较性状潜力，不是实际空间遭遇。零边可能来自未遇见、未选中、利用效率低或资源被共享限制，不能单凭零边判断生理不相容。


初始网络边不代表演化寄主转换；标准化偏好、潜在利用能力与实际取食需分别解释。当前参数仍为理论示例。
